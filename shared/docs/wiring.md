## Blocking discovery: `uses` imports are not implemented

The 1994 sources import shared library code with `uses "free"` /
`uses "method"` etc. Our compiler parses and **ignores** the directive, and
every call to a library routine silently compiles to nothing (surfaced by
the M0.5 warnings; ~1,610 across the corpus). The missing routines are real:
`scrollBack` (FREE.UNK:121), `safePlaySFX` (:752/:762), `getPeriod` (:703),
`killProcess` (:773), and more — 33 routines in FREE.UNK alone.

**Evidence for the correct implementation:** base-game bytecode is full of
cross-class calls into the compiled library classes — MYTHRAN alone calls
`0581:28F9` (class 0x581 = FREE) dozens of times, always as
`push args… / 11 81 05 xx xx / 6E xx (add sp)`. So the 1994 compiler
resolved `uses`-imported routines to **`0x11` calls into the provider
class** at known offsets. Our FREE.UNK compiles and replaces base class
0x581, so the provider offsets exist in our built FLX today; calls just
never got emitted.

**Required compiler work (gates most of M1 wiring):**
1. After compiling a provider file (FREE, METHOD…), record each
   routine/process name → (class_id, code offset) in the symbol table.
2. `uses "x"` makes that provider's routines resolvable in the consumer;
   emit `0x11 class:offset` with the base-game arg/cleanup convention
   (`add sp -N`), or `0x57 spawn` for `spawn routine(...) -> return`.
3. Compile order already puts LOST VALE/ (with FREE.UNK) first.
4. Same-class process spawn (`spawn puppet(lb)` inside LORDBRIT) — resolve
   to own class id + the process's code offset. Currently emits nothing.
5. Affected consumers recompile to working code with zero source changes.

Note: our recompiled FREE/METHOD replace working base classes, and their
own internal cross-calls silently no-op today — this work also repairs the
five modified base classes, not just the LV event scripts.

## Quest step 1: LORDBRIT (Lord British's message)

The scene (LORDBRIT.UNK): LB apparition materializes near the Avatar,
sparkle VFX, animated puppet process, delivers the message directing the
Avatar to Mythran, sets `lbDone`, vanishes. Self-guards with `lbStarted`.

**Trigger design (mechanism: UnkEgg, DD-007a):**
- Place a shape-73 egg (quality = pinned scene-class id − 0x47F) plus a
  TypeLordBritish apparition item adjacent to it.
- New lv-new egg class (e.g. `TypeEggLBScene`): `hatch()` does
  `spawn TypeLordBritish() -> return;`. Compiled LORDBRIT has `use()` at
  offset 0x0080, which is exactly the cross-class spawn convention the
  codegen already emits. Prereq: build must pre-register manifest class
  pins into the symbol table (today `load_manifest` pins flags only, so
  `TypeLordBritish` does not resolve from another file).

**Repairs needed before the scene plays correctly:**
| Issue | Root cause | Fix |
|-------|-----------|-----|
| `spawn puppet(lb)` emits nothing | same-class spawn unsupported | compiler work item 4 above |
| `scrollBack(25)` no-op | FREE routine, `uses` unimplemented | compiler work items 1-3 |
| `Avatar.turnToFace(...)` no-op | not an intrinsic; base implements facing in library/METHOD code | resolve during `uses` work (find the 1994 provider) |
| `[[PT_DEFAULT, referent]]` compiles to `push 0` (stack junk) | pragma unhandled | compile to nothing; map `referent` identifier to `this` |
| Sparkles: `TypeMagicSparkle = 73` in TYPE_SHAPES | **wrong** — 73 is the invisible UnkEgg shape (TYPE_SHAPES trap #3) | real sparkle VFX is shape 338 (prop-audit finding); fix TYPE_SHAPES |
| Apparition: `TypeLordBritish = 400` = "fire field" | TYPE_SHAPES trap #4 | placeholder candidate: shape **411 "ghost"** (needs ≥10 frames for the puppet animation — verify frame count); real LB art is an art-audit item |

**Placement (DECIDED by Douglas 2026-07-03):** (a) primary + (c) backstop,
both live in the shipped build — the `lbStarted` guard makes duplicate
eggs harmless (first to fire wins, the rest go inert forever):
- (a) Tenebrae chokepoint (drawbridge/gate style spot every route
  funnels through, not an open plaza) — catches any save in normal play.
  **Correction 2026-10-09:** the spot chosen (the grass south of Tenebrae's
  south gate, Map 39) lies outside the city walls, and no walking route
  reached it: the only one went through the east gate's teleport egg to
  Map 40 (`docs/playtest-2026-10-09-full-run-1-18.md` finding 1). A tunnel
  through the gate wall's east niche now opens a walked lane from the city
  (`build_map_39.py` TENEBRAE_LANE_*, asserted by `test_map39_lane.py`).
- (c) Map 8 Plateau approach — ordering backstop: nobody reaches Mythran
  without `lbDone`.
- (b) new-game start area: TEST-ONLY, behind a builder flag (e.g.
  `--lb-test-egg` or a module constant, default OFF) for quick fresh-game
  verification runs. Never on in a release build (pacing: fires the
  post-mid-game hook at minute one).

**Shape verification (2026-07-03, from U8SHAPES.FLX frame counts):**
- Apparition: shape 411 "ghost" has 201 frames — covers the puppet
  animation (frames 0-9). Adopted placeholder; real LB art stays on the
  art-audit list.
- Sparkles: **RESOLVED — TypeMagicSparkle = shape 587** (30 frames),
  proven from retail bytecode: base STRATOS.UNK source says
  `magic.create(TypeMagicSparkle, 11)` and the shipped STRATOS class
  (0x181, offset 149C) compiles it as `push byte 11; push 024Bh;
  Item::create` — 0x24B = 587. TYPE_SHAPES' value of 73 (the invisible
  egg) is trap #5; the wiring task fixes the table entry to 587. This
  source-vs-retail-bytecode comparison is the authoritative method for
  auditing any TYPE_SHAPES entry whose type appears in a U8/ base source.

**Verification: PASSED IN-GAME 2026-07-04** (fresh game,
`MainActor::teleport 39 17150 20000 48`, walk to the gate): scene plays
anchored on the apparition (bark, camera pan, sparkles shape 587, full
message, sparkles, ghost destroyed), `lbDone` reads 1
(`UCMachine::getGlobal 0x6A6 1`), and Mythran routes to the LV intro
("Ah. So the message has arrived at last...") without any `setGlobal`.
Getting here surfaced and fixed FOUR systemic codegen bugs (commits
0cea91f, d615197, 8f5e28b): intrinsic/call args must push right-to-left
(itemptr on top), Item locals pass as `push addr` 0x4B slot pointers
(I_create writes the objid back through them), spawns need the full
retail frame (push pid / args / null-this dword for spawn's
unconditional pop4 / implies), and loopscripts emit reversed (the loop
opcode pops them back off the stack forward). Every prior "verified"
path used only 0-1 arg intrinsics and container searches, which is why
none of this bit earlier.

**Known cosmetic follow-ups:** (1) the placement NOT visited keeps its
apparition item standing around after the scene runs elsewhere — fixed
2026-07-04 by LBSCENE.UNK's hatch(): when `lbStarted` is already set,
the spent hatch destroys any TypeLordBritish within 256 instead of
spawning the scene (needs one in-game confirmation pass). (2) An
intermittent whole-screen blackout right after the cross-map debug
teleport, at the avatar's first rotation — all FIXED items vanish,
avatar + dynamic items still render, re-running the same teleport
restores permanently. Engine fast-area/camera behavior on debug
teleports, not map data (the grass lane is FIXED|SOLID|LAND at the
correct z); normal egg-based travel doesn't hit it. Tracked, not
chased.

## Quest steps 3-4: COLPUZZL (elemental column puzzle)

**Wired 2026-07-04 (awaiting in-game verification).** The recovered 1994
design won over the compiled sketch: each pillar is destroyed by using
the OPPOSITE element's talisman (fire<->water, earth<->air) on the
receptacle beside it; order does not matter; all four destroyed opens
the passage. Decisions (Douglas, 2026-07-04): receptacle-driven
interaction; the MAP's element-frame mapping wins (0=Earth 1=Air 2=Fire
3=Water — design doc updated); solid-barrier gate; guardian escalation
(FREE.UNK makeAgent chain, never triggered even in 1994) deferred.

- **Class:** TypeReceptacle (COLPUZZL.UNK rewrite), pinned 1144/0x478 —
  npcnum dispatch is byte-limited to classes 1024-1279, so it CANNOT
  auto-append at 1431+; 1144 sits in the empty base-FLX gap 1088-1153,
  outside the Actor-promotion range 100-116, and npcnum 120 is unused by
  every base-map item (scan 2026-07-04). The retired EggColumnPuzzle pin
  1449 and flags columnsActivated/columnCorrectOrder stay (append-only).
- **Mechanics:** use() reads getQuality() (201 Earth / 202 Air / 203
  Fire / 204 Water), container-searches the Avatar for the opposite
  talisman (shape 580, frame = opposite element), consumes it, sparkle
  burst + QUAKE3 rumble, destroys the adjacent pillar (area 300, only
  its own pillar in range), sets the retail-shared *ColumnDestroyed
  flag, barks the design doc's lines. Wrong element barks the repel line
  (5-damage pushback deferred until receiveHit/hurl proven). Fourth
  pillar: allColumnsDestroyed, destroys the quality-299 sealing boulders.
- **Map 11:** both the Four Pillars chamber and the Teleporter Pad room
  were fully sealed boxes — carved an aligned 256-unit doorway (chamber
  south wall i=10 / pad north wall i=2, x 8704-8959) and plugged it with
  two shape-66 boulders (FIXED|SOLID 4x4x5, quality 299). Receptacles
  carry npcnum 120.
- **snddefs RECOVERED (2026-07-04):** SOUND.FLX entry 0 is the original
  8-byte-per-record sample-name table; sound number = index + 1. Proven
  by 20+ source-to-retail bytecode matches (MORDEA/STRATOS/AVATAR/
  AIRSPEL/POTION...). Full 220-name table now in u8c_symbols.py
  SND_CONSTANTS; killed the SFX push-0 warnings in COLPUZZL, CLCLIMB,
  ENDGAME, EAPUZL and dozens of latent sites across the 1994 corpus
  (QUAKE3=49, MAGIC1=54, LTNING1A=6, WIND4=116, MAGIC3=58, ...).
- **Verification plan:** fresh game, `MainActor::teleport 11 9728 1536 0`
  (entry hall); collect the four talismans (Earth (2048,5632), Air
  (17152,5120,z100), Fire (5632,18944), Water (12800,18944)); pillar
  chamber at (8192,20992); use each receptacle; confirm barks/flags
  (`UCMachine::getGlobal` — WaterColumnDestroyed 0x6A1, Fire 0x6A2,
  Earth 0x6A3, Air 0x6A4, allColumnsDestroyed 0x6EC per manifest);
  boulders vanish; teleporter to Map 10 works. NOTE: Map 11 has never
  been visually tested — expect a terrain/connectivity punch list from

> **Correction (2026-07-25 orphan triage — read before acting on the two
> mechanism assignments above).** LORDBRIT, COLPUZZL and PLNTST are now
> wired; 18 shipped classes remain unreachable and one pin (EGGCOLUMNPUZZLE)

> because of an id-range limit not accounted for at the time:
>
> **`npcNum` is a single byte in the map record**, so the LV patch's
> `class = npcNum + 1024` can only address classes **1025-1279**, and Actor
> promotion (map.cpp) is narrower still at npcNum **100-116 → classes
> 1124-1140**. The manifest cursor hands out ids from 1431 up, all outside
> both windows.
>
> - **SIGRID is pinned at 1452**, so the "npcnum mechanism" cannot reach her
>   at any npcNum value. She needs either a new pin inside the Actor window
>   (free slots: npcNum 100-104, 108-111, 114) or a Mythran-style wrapper
>   class that calls 1452. This blocks quest steps 11-12.
> - **The minor-item classes are pinned at 1431-1446**, so "shape dispatch
>   (class = shape id)" would require re-pinning each onto its shape's id,
>   i.e. replacing the base game's class for that shape. The alternatives are
>   the npcNum window (what TypeReceptacle already does, scoped per placement)
>   or leaving the flavour items inert.
>
> The event eggs are unaffected: UnkEgg quality is a 16-bit word, so
> `class = quality + 0x47F` reaches any id. Full per-class verdicts and the
> recommended order are in `docs/reviews/2026-07-25-orphan-triage.md`.

> **Resolved (2026-07-26, decision D).** SIGRID was re-pinned to class 1126
> (npcNum 102) on 2026-07-25. The item classes took the npcNum route, not
> shape dispatch: nine were re-pinned into **1252-1260 (npcNum 228-236)**,
